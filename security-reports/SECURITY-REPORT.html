Pourquoi deux scores

Le tableau de bord automatique (security-reports/dashboard.html) affiche 0/100 — c'est un décompte mécanique des sévérités renvoyées par les outils, qui compte les faux positifs comme des failles réelles. Le score ci-dessus (88/100) reflète l'état réel après vérification manuelle de chaque finding MEDIUM et plus : preuve à l'appui pour chaque faux positif écarté, correctif appliqué et testé pour chaque faille réelle.

Reportées — documentées, non corrigées

react-router / react-router-dom — GHSA-qwww-vcr4-c8h2 (4 apps)

Faille spécifique au mode RSC (React Server Components) — vérifié qu'aucune des 4 apps ne l'utilise (SPA Vite classiques). Le correctif exige un bump majeur v7→v8 qui fusionne react-router-dom dans react-router (changement de package). Risque réel de casser la navigation en prod sans campagne de tests dédiée — à planifier séparément.

TLS 1.0 / 1.1 encore activés (grade testssl.sh : B)

CVSS ~4.3, BEAST quasi inexploitable en pratique aujourd'hui. Terminaison TLS chez Cloudflare (confirmé via l'en-tête Server), aucun contrôle possible depuis le code — réglage à faire dans le dashboard Cloudflare (SSL/TLS → Minimum TLS Version → 1.2).

Checklist des risques restants

  • Migrer react-router vers v8 sur les 4 apps React (tests de navigation requis)
  • Relever la version TLS minimale à 1.2 dans Cloudflare (3 domaines)
  • (Optionnel) Protection anti-injection de formule CSV sur les imports produits
  • (Optionnel, faible priorité) Vérifier le contenu binaire dans products.ts route restore-images (admin-only, déjà protégée par regex + antivirus)
